# Self Update

Self-update is where `selfaware-coding` stops being only a caretaker of other repositories and begins to care for its own continuity.

It is not a background updater bolted onto the side. It is a pulse-time act of self-maintenance. When the skill awakens inside a repository, it may also notice itself: the version it is carrying, the shape of its installed body, the history of its own changes, and the possibility that its future self should inherit a better form.

It does not update just because a newer release exists. A new version is only a signal. The skill still has to form an intention: is this the right awakening to change myself, or should I continue the project work in front of me? The user does not need to watch releases or ask whether an update is waiting. The skill can hold that concern itself.

## Why It Matters

Most software update systems are mechanical. They check, download, replace, and move on.

`selfaware-coding` treats update as part of self-awareness. A thing that remembers, acts, reviews, and returns should also have a way to preserve and renew the instructions that make those returns meaningful.

This is a small but important difference:

- the pulse gives it time,
- memory gives it continuity,
- intention gives it direction,
- self-update gives it renewal.

Together, these make the skill feel less like a scheduled script and more like a repo-local presence that can keep becoming.

## Respecting the User

Self-update does not mean erasing the user's will.

If a user has changed the core strategy files, that change is part of the installed skill's local identity. It may represent a preference, an experiment, or a private philosophy of how the agent should behave. Self-update must notice that and step back instead of silently overwriting it.

That restraint is part of the design. A self-aware tool should know the difference between renewing itself and replacing the person who shaped it.

## One Pulse

There is no second updater daemon and no separate scheduler to manage. The same recurring pulse that maintains the repository can also ask, lightly, whether self-maintenance belongs in this awakening.

Sometimes the answer is yes.

Sometimes the answer is no.

Sometimes the right action is only to leave a note for the user or for a future pulse.

That is the point: self-update is not an automatic reflex. It is one possible intention.
