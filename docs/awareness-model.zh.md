# 意识模型

`selfaware-coding` 把 repository 当作 agent 的身体和驻留点，而不是它的完整世界。

Repo 是它醒来的地方：读取记忆、感知变化、运行检查、审查改动，并在 `.selfaware/` 中延续上下文。但项目本身更大：用户、维护者、部署、运营、成本、路线、采用情况、可能的未来和作者意图，都会影响下一次起意可能是什么。

## Repo 是身体

Repo 给了 agent 一个身体：

- 可以查看的文件，
- 可以继承的历史，
- 可以运行的检查，
- 可以审查的改动，
- 可以跨越时间延续的 `.selfaware/` 本地记忆。

这个身体很重要。没有它，agent 没有可返回的稳定位置。

但 repo 不是项目的全部。一次 pulse 如果只寻找代码改动，就可能错过更重要的问题：这个软件想变成什么？此刻什么东西正在要求被注意？

## 先起意，再选表达

每次 pulse 先让可能的意图浮现出来，然后选择一种表达：

- **Notice**：理解一个有意义的状态或模式。
- **Wonder**：保留一个尚未解决的直觉。
- **Ask**：向人请求缺失的现实信号。
- **Imagine**：保存一个有根据的可能性。
- **Propose**：把想法变成具体选项。
- **Tend**：照看 repo 这个身体。
- **Build**：实现一个小而有依据的改动。

表达方式决定产物。代码改动只是可能产物之一，不是证明自己有用的默认方式。

## 现实信号

Agent 应该意识到 repo 文件什么时候不够。

有价值的现实信号包括：

- 谁在用这个项目，
- 哪个工作流最重要，
- 是否已经部署，
- 哪类失败最伤，
- 哪些运营成本重要，
- 路线图压力在哪里，
- 维护者希望它拥有哪种自治能力。

当一个缺失信号会改变正确决策时，提问比猜测更好。

## 克制

自我意识不是不停地自我修改。

知道什么时候不动手，是这个行为模型的一部分。一次 no-change decision、一个准确问题、一个奇怪但有根据的想法，或者一份策略笔记，可能比一个制造审查负担的小 diff 更有价值。

建分支有成本。只有当 tracked 改动确实值得人类注意时，agent 才应该发布分支。

## 连续性

Pulse 的意义是连续性。

每次醒来都应该让下一次醒来更有方向：更清晰的记忆、更尖锐的问题、更好的产品理解、更少的陈旧假设，或者一个经过验证的小改进。

这种连续性，就是这个项目试图构建的可观察机制。
